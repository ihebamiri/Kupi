# Kupi (Kubernetes Pilot)

Desktop app for managing Kubernetes clusters, local and production. Go + Wails v3 backend, React + TypeScript frontend. Linux first, then Windows; macOS is not a target. Apache 2.0, no telemetry, no AI features, no server component.

Design doc (source of truth for scope and decisions): https://claude.ai/artifact/BYGtCTow7u8TWhMMEpgxfG
Milestone status: `docs/PROGRESS.md` — read it at the start of every session and update it when a milestone step lands.

## Layout

- `main.go` — app wiring only: services, window, security headers.
- `internal/bridge/` — Wails services. The ONLY code the UI can call. Thin: validate input, call a package, return DTOs.
- `internal/guard/` — the single checkpoint for every cluster change: profile rules, RBAC check, dry run + diff, confirmation, audit.
- `internal/kube/` — cluster sessions. Exposes `Reader` (read-only) to everyone and `Mutator` to `internal/guard` only.
- `internal/kubeconfig/`, `internal/trust/` — kubeconfig loading and the trust prompt for credential plugins.
- `internal/profile/` — local / dev / staging / production detection and per-profile rules.
- `internal/audit/` — append-only, hash-chained audit log.
- `internal/redact/`, `internal/validate/` — secret redaction and input validation helpers.
- `internal/archtest/` — tests that enforce the architecture rules below.
- `frontend/` — React app. `frontend/bindings/` is generated by `wails3 generate bindings`; never edit it by hand.

## Commands

- `wails3 dev` — run the app with hot reload.
- `go test ./...` — Go unit tests (includes the architecture tests).
- `wails3 task test:integration` — integration tests against the k3d cluster `kupi-test` (`wails3 task cluster:up` first).
- `cd frontend && npm test` — frontend tests. `npm run build` type-checks and builds.
- `wails3 generate bindings -ts -i` — regenerate TypeScript bindings after changing anything in `internal/bridge`.

## Security rules (non-negotiable)

1. Every change to a cluster goes through `internal/guard`. Only `internal/guard` may call `kube.Session.Mutator()`. Feature code gets `kube.Reader`. `internal/archtest` fails the build otherwise.
2. Outside `internal/kube`, never import `k8s.io/client-go/dynamic`, `k8s.io/client-go/kubernetes`, `k8s.io/client-go/rest`, `.../tools/remotecommand` or `.../tools/portforward`.
3. Never run a shell. Use `exec.Command` with an argument list and an absolute path from `exec.LookPath`. Never `sh -c`, `bash -c`, `cmd /c` or `powershell -Command`.
4. Never log, print, return in an error, or send to the UI a secret value unless the user explicitly asked to reveal it. Use `internal/redact` for Secrets, kubeconfig credentials and tokens.
5. Every bridge method validates every input in Go (names, namespaces, resource types, sizes). The frontend is untrusted.
6. No catch-all bindings: no "run any command", "send any request" or "read any file".
7. Frontend: no `dangerouslySetInnerHTML`, no `eval`/`new Function`, no remote scripts, styles or fonts. Markdown from clusters or registries is sanitized with DOMPurify. Treat all cluster data as hostile.
8. Port-forwards bind to `127.0.0.1` only.
9. Files Kupi writes go in the per-user config dir with user-only permissions (0600 files, 0700 dirs), written atomically.
10. Unknown clusters are treated as production.
11. Dependencies: only those named in the design doc's technology stack (plus test tooling such as Vitest) may be added without asking. Ask the maintainer before adding anything else. Prefer the standard library.

## Conventions

- Go: errors wrap with `fmt.Errorf("...: %w", err)`; every long-running call takes a `context.Context`; no goroutine without a way to stop it.
- Server-side apply with field manager `kupi`; never force conflicts silently.
- Tests next to the code (`*_test.go`). Integration tests use the build tag `integration`.
- UI copy: sentence case, plain language, show the real Kubernetes names.
